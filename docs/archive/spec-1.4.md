# Сайт-лента · движок · спецификация 1.4

Версия спецификации: 1.4 от 04.10.2026 (1.3, 1.2, 1.1 и 1.0 —
03–04.10.2026). Владелец: Вячеслав. Разработчик: Вадим.

## Что нового в 1.4

Места изменений помечены **\[NEW 1.4\]**.

1.  **Режим сайта: «Простой» / «С табами».** Выбирается при создании
    сайта. Простой — одна лента плиток, табов нет никогда, админка не
    показывает разделы. С табами — табы видны сразу, даже если раздел
    один. Табы больше не появляются сами от числа разделов.
2.  **Плитка уровня 1: страница или поп-ап — по выбору для каждой
    плитки.** Простое описание монастыря — поп-ап (карточка). Если есть
    плитки, вина, услуги, пожертвование — страница.
3.  **Плитка-страница получает Текст (до 3000) и Локацию.** Верх её
    страницы собирается из самой плитки: компактное фото 3:2 рядом с
    названием и текстом, ниже «Как добраться» с мини-картой. Без
    элементов страница статичная. Координаты плиток-страниц идут на
    карту главной. «Первая плитка» больше не создаётся сама.
4.  **Текст карточки — до 3000 знаков** (был 1500).
5.  **Новый элемент «Вино».** Карточка вина: фото 4:5, тип, сорт, год,
    цена (по переключателю раздела), описание в поп-апе. Сетка 3 / 3
    / 2. Без кнопки «Купить». Поля — по карточке вина в проекте Вадима.
6.  **Новые эталоны:** `ЭНОТИС_сайт_макет_v4.html` и
    `ЭНОТИС_админка_макет_v8.html` (заменяют v3 и v7).

## Что строим

Один движок сайта-ленты из плиток и одну админку к нему. Любой сайт
этого типа собирается из одного и того же кода, меняется только контент
в базе.

Применения:

- миссионерские сайты (первый — palomnik.site, «1+3+13»);
- агрегатор монастырей **\[NEW 1.1\]**: над лентой главной табы стран
  (сейчас Грузия, в перспективе 15–20); в разделе страны — плитки
  монастырей; у каждого монастыря своя страница с описанием, услугами и
  пожертвованием;
- сайт отдельного монастыря. Движок будет продаваться монастырям под
  ключ.

Винный магазин ЭНОТИС (каталог, корзина, 6 языков) — другой проект, сюда
не входит.

## Принципы (не нарушать)

1.  **Контент только в базе.** В коде нет текстов сайта. Служебные
    подписи интерфейса («Подробнее», «← Назад», «К списку» и т. п.)
    лежат в одном языковом файле `lang/ru.php`.
2.  **Два уровня, глубже нельзя.** Уровень 1 — главная, уровень 2 —
    страница плитки. Карточка открывается окном поверх страницы, это не
    уровень. **\[NEW 1.1\]** Раздел (таб) — тоже не уровень: это
    отдельная лента уровня 1.
3.  **Один рендер.** Публичный сайт и превью в админке собираются одними
    и теми же PHP-шаблонами. Отдельной JS-копии сайта в админке нет.
4.  **Сайт работает без JS.** Весь контент и все ссылки отдаются
    сервером в HTML. JS только улучшает: окна, карта, прячущаяся шапка.
5.  **Просто.** PHP 8.1+, SQLite через PDO, ванильный JS, без
    фреймворков и сборщиков. Библиотеки: Cropper.js (админка), Leaflet
    (карта). Хранить локально, не брать с CDN.
6.  **Многоязычность заложена в базе с первого дня.** Тексты хранятся с
    кодом языка. В версии 1 работает один язык (ru), переключателя нет.
7.  **Не делаем в версии 1:** аналитику, черновики, роли пользователей,
    видео в плитках, переключатель языков, **\[NEW 1.1\]** форму заказа
    услуги на сайте и деление платежа (сплит) — в v1 услуга ведёт по
    ссылке на оплату.
8.  **\[NEW 1.1\] Ядро обновляется без ручной правки баз.** Любое
    изменение структуры базы — только новой миграцией (модель данных,
    раздел 8).

# Модель данных (общая для сайта и админки)

## 1. Установка = один сайт

Каждый сайт — отдельная установка: код движка, файл `data/site.sqlite`,
папка `data/uploads/` и `config.php` с адресом сайта и доступом в
админку. Код движка во всех установках одинаковый. Чтобы обновить
движок, заменяют папку с кодом, а база и фото остаются. **\[NEW 1.1\]**
Агрегатор — такая же установка: каждая страна — раздел (таб), монастыри
— плитки-страницы уровня 1 в разделе, на странице монастыря (уровень 2)
— описание, карточки, услуги, пожертвование.

Резервная копия = копия `data/` (один файл базы + фото). **\[NEW 1.1\]**
Перед каждой миграцией движок сам копирует базу в `data/backups/`
(раздел 8).

## 2. Правила структуры

| **Правило**                                                                                                                | **Как обеспечить**                        |
|----------------------------------------------------------------------------------------------------------------------------|-------------------------------------------|
| Уровень 1: `parent_id = NULL`                                                                                              | —                                         |
| Уровень 2: родитель — плитка уровня 1 с `open_mode = 'page'`                                                               | Проверка при сохранении                   |
| Глубже уровня 2 нельзя                                                                                                     | Проверка при сохранении                   |
| Предисловие, Карта, Оплата, Послесловие — не больше одного на уровень                                                      | Частичный уникальный индекс + проверка    |
| Плитка уровня 2 всегда `open_mode = 'card'`                                                                                | Проверка при сохранении                   |
| Плиток на уровне сколько угодно                                                                                            | —                                         |
| Порядок — `position` внутри родителя, свободный                                                                            | Перетаскивание в админке                  |
| **\[NEW 1.1\]** Элемент уровня 1 принадлежит ровно одному разделу (`section_id`); элементы уровня 2 — разделу своей плитки | Проверка при сохранении                   |
| **\[NEW 1.1\]** «Один на уровень» считается внутри раздела                                                                 | Индекс по `(section_id, parent_id, type)` |
| **\[NEW 1.1\]** Услуг на уровне сколько угодно                                                                             | —                                         |

Рекомендуемый порядок (подсказка, не ограничение): Предисловие → плитки
и Карта → Оплата → Послесловие.

Если плитку-страницу переключили на «карточку», её элементы уровня 2
**не удаляются**: они хранятся, на сайте не показываются и вернутся,
если снова выбрать «Открыть страницу».

### \[NEW 1.1\] Разделы

- В установке всегда есть хотя бы один раздел. При установке создаётся
  раздел `main`.
- **\[NEW 1.4\]** **Режим «Простой»** (`site_mode = simple`) — раздел
  ровно один и скрыт от пользователя: табов нет никогда, адреса без
  префикса раздела (как в 1.0). Так работают отдельные сайты (монастыри
  Грузии, винодельни, palomnik.site).
- **\[NEW 1.4\]** **Режим «С табами»** (`site_mode = sections`) — на
  адресе всех разделов над лентой главной табы **всегда, даже если
  раздел один**; адреса начинаются со slug раздела (`/gruziya/…`). Табы
  больше не зависят от числа разделов.
- **\[NEW 1.2\]** Сколько разделов видно, зависит ещё и от адреса: адрес
  одного раздела всегда показывает только его (раздел 9).
- У раздела свои: название таба, slug, порядок, валюта, формат
  реквизитов (RU / GE / other), владелец, **\[NEW 1.3\]** сервис карт
  (Google / Яндекс). Язык раздела — задел на этап 2.

## 3. Схема SQLite

    PRAGMA foreign_keys = ON;
    PRAGMA journal_mode = WAL;

    -- [NEW 1.1] Версия схемы (раздел 8)
    CREATE TABLE schema_version (
      version    INTEGER NOT NULL,
      applied_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
    );

    CREATE TABLE languages (
      code        TEXT PRIMARY KEY,          -- 'ru', позже 'ka', 'en'
      name        TEXT NOT NULL,
      is_default  INTEGER NOT NULL DEFAULT 0,
      is_active   INTEGER NOT NULL DEFAULT 1
    );

    -- Настройки без языка: шапка, подвал
    CREATE TABLE settings (
      key   TEXT PRIMARY KEY,                -- header_show, header_burger (auto|on|off),
      value TEXT                             -- footer_show, footer_email, footer_phone
    );

    -- Настройки с языком
    CREATE TABLE settings_i18n (
      key   TEXT NOT NULL,                   -- site_title, site_description
      lang  TEXT NOT NULL REFERENCES languages(code),
      value TEXT,
      PRIMARY KEY (key, lang)
    );

    CREATE TABLE photos (
      id            INTEGER PRIMARY KEY,
      original_path TEXT NOT NULL,           -- исходник, хранится всегда
      crop_x REAL, crop_y REAL, crop_w REAL, crop_h REAL,  -- в пикселях исходника
      rotate        INTEGER NOT NULL DEFAULT 0,            -- 0, 90, 180, 270
      path_1600     TEXT,                    -- 1600×1067, основной
      path_800      TEXT,                    -- 800×533
      path_400      TEXT,                    -- 400×267
      created_at    TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
    );

    -- [NEW 1.1] Владелец: ИП / организация, чьи реквизиты в подвале
    CREATE TABLE operators (
      id        INTEGER PRIMARY KEY,
      name      TEXT NOT NULL,          -- «ИП Иванов Иван Иванович»
      country   TEXT NOT NULL DEFAULT 'RU' CHECK (country IN ('RU','GE','other')),
      tax_id    TEXT,                   -- ИНН (RU) / идентификационный код (GE)
      reg_no    TEXT,                   -- ОГРНИП / ОГРН (RU), пусто для GE
      address   TEXT,
      email     TEXT
    );

    -- [NEW 1.1] Разделы (табы)
    CREATE TABLE sections (
      id          INTEGER PRIMARY KEY,
      slug        TEXT NOT NULL UNIQUE,
      position    INTEGER NOT NULL,
      hidden      INTEGER NOT NULL DEFAULT 0,
      currency    TEXT NOT NULL DEFAULT 'RUB',   -- RUB, GEL, EUR …
      req_format  TEXT NOT NULL DEFAULT 'RU' CHECK (req_format IN ('RU','GE','other')),
      operator_id INTEGER REFERENCES operators(id) ON DELETE SET NULL,
      maps        TEXT NOT NULL DEFAULT 'google' CHECK (maps IN ('google','yandex')),  -- [NEW 1.3] сервис карт в карточке
      show_prices INTEGER NOT NULL DEFAULT 1,        -- [NEW 1.4] показывать цены вин
      lang        TEXT REFERENCES languages(code)  -- задел, в v1 не используется
    );
    CREATE TABLE section_i18n (
      section_id INTEGER NOT NULL REFERENCES sections(id) ON DELETE CASCADE,
      lang       TEXT NOT NULL REFERENCES languages(code),
      title      TEXT,                   -- подпись таба
      PRIMARY KEY (section_id, lang)
    );

    -- [NEW 1.2] Адреса (домены) установки
    CREATE TABLE domains (
      host       TEXT PRIMARY KEY,          -- 'obiteli.site', 'georgia.obiteli.site'
      section_id INTEGER REFERENCES sections(id) ON DELETE SET NULL,  -- NULL = все разделы с табами
      position   INTEGER NOT NULL DEFAULT 0
    );
    CREATE TABLE domain_i18n (
      host  TEXT NOT NULL REFERENCES domains(host) ON DELETE CASCADE,
      lang  TEXT NOT NULL REFERENCES languages(code),
      site_title TEXT,                      -- название сайта на этом адресе
      PRIMARY KEY (host, lang)
    );

    -- [NEW 1.1] Документы: оферта, политика ПДн, cookies
    CREATE TABLE docs (
      key     TEXT PRIMARY KEY CHECK (key IN ('offer','privacy','cookies')),
      hidden  INTEGER NOT NULL DEFAULT 1
    );
    CREATE TABLE doc_i18n (
      key   TEXT NOT NULL REFERENCES docs(key) ON DELETE CASCADE,
      lang  TEXT NOT NULL REFERENCES languages(code),
      title TEXT,
      body  TEXT,
      PRIMARY KEY (key, lang)
    );

    CREATE TABLE elements (
      id         INTEGER PRIMARY KEY,
      section_id INTEGER NOT NULL REFERENCES sections(id) ON DELETE CASCADE,  -- [NEW 1.1]
      parent_id  INTEGER REFERENCES elements(id) ON DELETE CASCADE,
      type       TEXT NOT NULL CHECK (type IN ('intro','tile','map','pay','service','wine','outro')),  -- [NEW 1.1] service
      position   INTEGER NOT NULL,
      hidden     INTEGER NOT NULL DEFAULT 0,
      open_mode  TEXT CHECK (open_mode IN ('page','card')),  -- только для tile
      slug       TEXT,                                       -- только для tile
      fn_photo   INTEGER NOT NULL DEFAULT 0,
      fn_text    INTEGER NOT NULL DEFAULT 0,
      fn_place   INTEGER NOT NULL DEFAULT 0,
      fn_src     INTEGER NOT NULL DEFAULT 0,
      lat        REAL,
      lng        REAL,
      photo_id   INTEGER REFERENCES photos(id) ON DELETE SET NULL,
      link_url   TEXT,                                       -- [NEW 1.1] Услуга: ссылка на оплату
      price      REAL,                                       -- [NEW 1.1] Услуга: цена в валюте раздела, пусто = «по договорённости»
      created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,

## 4. Адреса (slug)

- Slug есть только у плиток. Создаётся автоматически из названия при

- **\[NEW 1.1\]** Slug плитки уникален внутри раздела и родителя. Slug

  меняется сам.

## 8. \[NEW 1.1\] Миграции и обновление движка

- Каждое изменение структуры базы — отдельный файл
  `app/migrations/NNN_название.sql` (001, 002, …). Применённые файлы не
  редактируются никогда, только добавляются новые.
- Таблица `schema_version` хранит номер последней применённой миграции.
- При каждом запросе `db.php` сравнивает номер в базе с последним
  файлом. Если есть новые миграции:
  1.  копирует `data/site.sqlite` в
      `data/backups/site_ГГГГММДД-ЧЧММ_vNNN.sqlite` (хранить последние
      10);
  2.  применяет недостающие миграции по порядку, каждую в транзакции;
  3.  при ошибке — откат, сайт показывает «Идёт обновление», в админке —
      текст ошибки; база остаётся рабочей копией.
- Обновление установки: заменить папку с кодом → первый запрос сам
  обновит базу. Ручных правок баз на установках нет.
- Константа `ENGINE_VERSION` в коде. Админка показывает версию движка и
  схемы в подвале админки.
- Тестовые данные (JSON) импортируются в базу любой версии через формат
  дерева (раздел 6), а не SQL-дампом.

## 9. \[NEW 1.2\] Адреса: «домен → раздел»

- Движок определяет адрес по заголовку `Host`. Если адреса нет в таблице
  `domains` — используется первый адрес (по `position`); в `config.php`
  можно запретить чужие адреса.
- **Адрес всех разделов** (`section_id = NULL`): общее предисловие, табы
  видимых разделов (**\[NEW 1.4\]** всегда в режиме «С табами», даже
  если раздел один), адреса страниц с префиксом раздела. В режиме
  «Простой» адреса-разделы не используются: любой адрес показывает
  единственный раздел.
- **Адрес одного раздела**: только этот раздел, без табов и без общего
  предисловия, адреса без префикса раздела (как в 1.0). Заголовок
  главной — название сайта этого адреса.
- Название сайта адреса (`domain_i18n.site_title`) — в шапке, подвале,
  `<title>`, `og:site_name`. Настройка `site_title` из 1.0 остаётся
  запасной.
- **Canonical.** Если у раздела есть свой адрес, canonical всех страниц
  раздела на любом адресе указывает на адрес раздела. Иначе — на адрес
  всех разделов.
- `sitemap.xml` и `robots.txt` строятся для текущего адреса: на адресе
  раздела — только его страницы; на общем адресе — страницы разделов без
  своего адреса.
- Документы (`/doc/…`) и владельцы общие для всех адресов; в подвале —
  владелец раздела страницы.
- Общее предисловие хранится в `settings_i18n`: ключи `hub_eyebrow`,
  `hub_title`, `hub_text`.

## 10. \[NEW 1.2\] Выгрузка и загрузка раздела

- **Выгрузить:** ZIP = `section.json` (раздел в формате дерева, раздел
  6, вместе с владельцем раздела) + папка `photos/` (исходники и
  параметры кадра).
- **Загрузить:** раздел добавляется как новый, скрытым. Совпадающий slug
  раздела получает `-2`; фото загружаются как новые; владелец
  добавляется, если такого (по названию и коду) ещё нет.
- Проверки — как при сохранении (ограничения, глубина, «один на
  уровень»). При ошибке ничего не записывается.
- Назначение: перенос страны в отдельную установку (другой владелец,
  продажа монастырю) и резервная копия одной страны.

## 12. \[NEW 1.4\] Режим сайта, плитка-страница, вино

### Режим сайта

- Настройка `settings.site_mode`: `simple` (по умолчанию) или
  `sections`.
- `simple`: в базе один раздел `main`, его настройки (валюта, формат
  реквизитов, владелец, сервис карт, цены вин) админка показывает как
  «Настройки сайта → Основное». Табов, переключателя разделов и привязки
  адресов к разделам нет.
- `sections`: всё как в 1.1–1.2, но табы на адресе всех разделов видны
  всегда.
- Переключение `simple → sections` — в любой момент: текущий раздел
  становится первым табом (админка просит подпись таба и slug).
- Переключение `sections → simple` — только если раздел один. Иначе
  админка сообщает: «Сначала оставьте один раздел (остальные удалите или
  выгрузите в отдельные установки)».
- В JSON дерева: `"site_mode": "simple"`. Нет поля: если разделов больше
  одного — `sections`, иначе `simple`.

### Плитка уровня 1: страница или карточка

- У плитки уровня 1 `open_mode` = `page` или `card`, выбирается для
  каждой плитки. На одном сайте можно смешивать.
- **Обеим** доступны функции Фото, Текст, Локация, Источник фото. Текст
  до 3000 знаков.
- Плитка-страница может быть **без элементов уровня 2** — тогда это
  статичная страница (описание + «Как добраться»).
- Карта: отметку получает видимая плитка с включённой Локацией и
  координатами — и карточка, и страница.

### Вино

| **Поле**           | **Где хранится**                                               | **Пример**   |
|--------------------|----------------------------------------------------------------|--------------|
| Название           | `element_i18n.title`                                           | Alaverdi Red |
| Сорт винограда     | `element_i18n.subtitle`                                        | Саперави     |
| Описание (до 3000) | `element_i18n.body`                                            | —            |
| Цвет               | `elements.wine_color` (`red`, `white`, `rose`, `amber`)        | красное      |
| Сладость           | `elements.wine_sweet` (`dry`, `semidry`, `semisweet`, `sweet`) | полусухое    |
| Год урожая         | `elements.vintage` (INTEGER)                                   | 2015         |
| Цена               | `elements.price` (как у Услуги), валюта раздела                | 45 ₾         |
| Фото               | `elements.photo_id`, пропорции 4:5                             | —            |

- **Поля — пример. Источник истины — карточка вина в проекте Вадима.**
  Если там поля другие (объём, крепость, регион и т. п.), Вадим берёт
  свои и правит эту таблицу. Механика (место в ленте, фото 4:5, сетка,
  поп-ап, цена по переключателю) остаётся.
- Страна и монастырь на карточке не хранятся у вина: страна = подпись
  раздела, монастырь = название плитки-страницы, на которой стоит вино.
  На уровне 1 вместо монастыря — название сайта.
- Вин на уровне сколько угодно. Вино доступно на уровне 2 и на уровне 1
  (если весь сайт — один монастырь).
- Миграция:
  `ALTER TABLE elements ADD COLUMN wine_color TEXT; … wine_sweet TEXT; … vintage INTEGER;`
  `ALTER TABLE sections ADD COLUMN show_prices INTEGER NOT NULL DEFAULT 1;`
  `ALTER TABLE photos ADD COLUMN aspect TEXT NOT NULL DEFAULT '3:2';` +
  новое значение `wine` в списке типов (пересоздание CHECK — по правилам
  SQLite, внутри миграции).

### Фото вина

| **Параметр**         | **Значение**                                                                                                                     |
|----------------------|----------------------------------------------------------------------------------------------------------------------------------|
| Пропорции            | 4:5 (вертикально)                                                                                                                |
| Итог                 | JPEG 1200×1500, плюс 600×750 и 300×375 для `srcset`                                                                              |
| Содержание           | Бутылка по центру на ровном светлом фоне. Готовые фото (например, из Higgsfield) загружаются как есть, редактор ставит рамку 4:5 |
| Нет фото             | Силуэт бутылки на фоне карточки                                                                                                  |

# Часть А. План реализации сайта

Предложение. Структуру папок Вадим может менять, принципы из CLAUDE.md —
нет.

## Структура

    /public            ← корень веб-сервера
      index.php        ← единая точка входа, маршрутизатор
      /assets          ← theme.css, site.css, site.js, fonts/, leaflet/, icons/
      /uploads         ← ссылка или алиас на data/uploads
    /app
      db.php           ← PDO, PRAGMA, миграции
      repo.php         ← чтение дерева сайта (одна выборка → дерево в памяти)
      render.php       ← render_page($tree, $route, $options)
      seo.php          ← title, description, OG, JSON-LD, sitemap
      slug.php         ← транслитерация
      /templates       ← layout, header, footer, intro, tile, map, pay, card, pay_modal, 404
    /lang/ru.php       ← служебные подписи
    /data              ← site.sqlite, uploads/ (вне веб-корня, кроме uploads)
    config.php

## Маршрутизация

`index.php` разбирает путь на 0–2 сегмента:

- 0 сегментов → главная;
- 1 сегмент → плитка уровня 1 с таким slug: страница → уровень 2,
  карточка → главная + открытая карточка;
- 2 сегмента → плитка-страница + плитка уровня 2 внутри → уровень 2 +
  открытая карточка;
- иначе, если не найдено или скрыто → 404.

Правило Apache или Nginx: всё, что не файл, отдаётся в `index.php`.

**\[NEW 1.1\]** При двух и больше видимых разделах первый сегмент — slug
раздела, дальше разбор как выше (до 3 сегментов). `doc/{key}` —
документ. Параметр `?fragment=1` у главной раздела отдаёт только ленту
(для табов).

## Рендер

- `render_page($tree, $route, $options)` — **одна функция для сайта и
  превью**. Параметр `$options['preview'] = true` добавляет:
  - атрибут `data-el="{id}"` на каждый элемент, а также на шапку
    (`data-el="header"`) и подвал (`data-el="footer"`);
  - подсветку выбранного элемента (`data-selected`);
  - скрипт, который по нажатию на элемент отправляет
    `postMessage({select: id})` в админку и не переходит по ссылкам.
- Дерево читается одним запросом с `JOIN element_i18n` по текущему
  языку, собирается в памяти.
- Плитки, идущие подряд, группируются в `<div class="tiles">`.
- Карточка и окно оплаты — `<dialog>` или div-оверлей. Карточка,
  открытая по адресу, рендерится открытой сразу.
- Окно оплаты рендерится в HTML скрытым. Ссылки хранятся в `data-href`
  кнопок, не в видимом тексте.

В форме: миниатюра (или «нет фото»), кнопки «Загрузить фото» / «Изменить

Редактор — окно поверх админки:

- **\[NEW 1.4\]** Рамка 3:2 для плиток, предисловий и послесловий; **4:5
  для вина** (итог 1200×1500).
- Рамка всегда 3:2, неподвижна; фото двигается внутри неё
  (перетаскивание) и масштабируется (ползунок «Масштаб» 1–4× и колесо
  мыши).
- «Повернуть на 90°» — после поворота фото само увеличивается, чтобы
  закрыть рамку без пустых полей.
- «Сбросить» — исходное положение.
- Справа предпросмотр «Как будет выглядеть»: мини-сетки компьютера (3
  плитки), планшета (2), телефона (1) с этим фото на своём месте.
  Обновляется при движении.
- Подписи: «Рамка всегда 3:2. Перетащите фото, чтобы главное попало в
  рамку. Колесо мыши тоже меняет масштаб», «Тексты и настройки элемента
  при замене фото не меняются», «Итог: 1600×1067 px, JPEG, сжатие
  автоматически».
- «Отмена» / «Применить».

Логика:

- «Загрузить» или «Заменить»: файл сначала уходит на сервер как
  исходник, затем открывается редактор.
- «Изменить кадр»: редактор открывается на **исходнике** с прежней
  рамкой и поворотом.
- «Применить»: на сервер уходят координаты рамки и поворот, сервер режет
  1600/800/400 из исходника (см. модель данных, раздел 5).
- «Заменить фото» меняет только фото. Название, тексты, координаты и
  функции остаются.
- Для фото меньше 1600 px по ширине рамки — предупреждение «Фото
  маленькое, на большом экране может быть нечётким», но применить можно.

## Б10. Сохранение

- Любое изменение — статус «Есть несохранённые изменения».
- «Сохранить» отправляет всё дерево. Сервер проверяет и записывает его
  одной транзакцией. Сохранение = сразу на сайте (черновиков нет).
- Если проверка не прошла, ничего не записывается. Список ошибок
  показывается над формой, нажатие на ошибку открывает элемент.
- Что проверяется перед записью (блокирует сохранение):
  - ограничения длины (модель данных, раздел 7);
  - не больше одного Предисловия, Карты, Оплаты, Послесловия на уровень;
  - глубина не больше 2, плитки уровня 2 — карточки;
  - координаты в допустимом диапазоне, обе или ни одной;
  - ссылки начинаются с `https://` (исключения: WhatsApp, Viber);
  - у включённой Оплаты включён хотя бы один способ, иначе
    предупреждение (не блокирует).
- При попытке закрыть вкладку с несохранёнными изменениями браузер
  спрашивает подтверждение.
- Ctrl/Cmd + S — сохранить.

    /public/assets/cropper/     ← Cropper.js 1.6.x, локально

Состояние админки — одно дерево сайта в JS (формат из
`модель_данных.md`, раздел 6). Дерево, форма и превью строятся из него.

## API

| **Метод и путь**              | **Что делает**                                                                                                                                  | **Ответ**                                                    |
|-------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------|
| `GET api.php?a=tree`          | Дерево сайта из базы                                                                                                                            | JSON-дерево                                                  |
| `POST api.php?a=save`         | Проверить и записать всё дерево одной транзакцией; присвоить `id` и slug новым; удалить исчезнувшие элементы и их фото; вызвать `cache_clear()` | `{ok, tree}` или `{ok:false, errors:[{id, field, message}]}` |
| `POST api.php?a=preview`      | Отрисовать дерево **без записи**: `render_page($tree, $route, ['preview'=>true])`; `route` = главная / страница / карточка                      | HTML                                                         |
| `POST api.php?a=photo_upload` | Принять файл, сохранить исходник                                                                                                                | `{photo_id, original_url, width, height}`                    |
| `POST api.php?a=photo_crop`   | `{photo_id, x, y, w, h, rotate}` → нарезать 1600/800/400                                                                                        | `{url_1600, url_800, url_400}`                               |
| `POST api.php?a=qr_upload`    | Картинка QR как есть                                                                                                                            | `{url}`                                                      |

Фото загружаются сразу, а не при «Сохранить». Сиротские фото (загружены,
но не привязаны после сохранения) можно удалять раз в сутки или при
сохранении — на усмотрение Вадима.

## Превью

- `<iframe>`, ширина 1280 / 768 / 390, масштабирование
  `transform: scale()` под колонку.
- При изменении — `debounce(400 мс)` → `POST preview` →
  `iframe.srcdoc = html`. Перед заменой запомнить прокрутку и
  восстановить её после.
- Связь превью ↔ админка — через `postMessage`:
  - из превью: `{select: id}`, `{navigate: route}`;
  - в превью: `{highlight: id}`.
- Окна (карточка, оплата) в превью работают тем же `site.js`.

## Сохранение

- Транзакция: `BEGIN` → удалить отсутствующие → вставить новые →
  обновить существующие (`position` по порядку в массиве) → тексты в
  `element_i18n` для `lang` из дерева → способы оплаты → соцсети и
  настройки → `COMMIT`.
- Проверки — на сервере (обязательно) и в браузере (для подсказок).
  Источник истины — сервер.
- Тексты сохраняются как есть (plain text). Экранирование — при выводе в
  шаблонах (`htmlspecialchars`). HTML в полях не поддерживается.

## \[NEW 1.1\] Что меняется

- Дерево в JS — формат 1.1 (`operators`, `sections`, `docs`). `GET tree`
  и `POST save` работают со всем деревом сразу, включая все разделы.
- `POST preview` получает дерево и маршрут с разделом:
  `{section, page, card}`.
- Сохранение в транзакции дополнительно пишет владельцев, разделы,
  документы, способы оплаты (по `id`, удаляя исчезнувшие).
- Админка не меняет структуру базы. Структура — только миграциями.

## Безопасность

- Все запросы API — только после входа, с CSRF-токеном.
- Загрузки: проверка типа по содержимому (`finfo`), не по расширению;
  имя файла генерирует сервер; в `uploads` запрещено исполнение PHP.
- SVG для QR — очищать от скриптов или конвертировать в PNG.
